# Install the shop workspace

Read root README, docs/first-result.md, docs/providers.md, docs/architecture.md and docs/status.md. Preserve the selected e480 source relationship and actual UI. Keep Artisan, other-company accounts and private historical records outside this workspace.

1. Check Node22+/Python3.12+, disk and available ports18240–18243. Run `make install`, `make doctor`, `make build`, `make test` in the recipient's checkout. Installation fetches declared dependencies; tests use synthetic inputs and injected transports.
2. Run `make dev`, then the actual `#/prep` browser route. Verify the twelve generated sales, Sample chats source, desktop/phone behavior and collection service. `tools/first-result.py` provides a bounded loopback proof. Preserve failing output as evidence and fix ordinary portable startup defects in source.
3. Explain the workflow and proof tiers before provider commissioning. Merchant review, phone verification, Meta business authorization, group eligibility, share opening, accepted send, delivery and bank settlement are different facts.
4. Select the recipient's owning company/account and exact permitted operation before choosing its secrets/runtime. Use `tools/configure.py --secret NAME` for hidden terminal entry or `--secret-file NAME /absolute/private/file` for an owned mode0600 file. Never ask for secrets in chat or print private config. The doctor reports names/presence only.
5. Configure public origin, owned application package, bot number and Meta public identifiers. Keep the paired Android/API callback changes. Rebuild after public settings change. Run the provider preflight without network requests.
6. Keep synthetic and connected state separate. Back up each encryption key with its associated store. Use a dedicated HTTPS origin for secure account cookies and an isolated private state directory. Restrict ingress and account quotas for the intended audience.
7. Ask for operation-specific authorization when it spends provider money, sends messages, affects bank/fiscal records or publishes a deployment. Existing explicit session authorization remains valid. Configuration alone establishes neither provider acceptance nor permission to operate.
8. Run the smallest authorized real provider/device acceptance and retain aggregate/status evidence. Keep chat bodies, contacts, phone/wallet records and account credentials private. Reconcile uncertain external outcomes before retrying one-time work.
9. Record exact source hash, configuration variable names, runtime owner, scope, checks and readiness. Preserve third-party notices. Summarize the useful result and remaining external proof concisely.

Use the original browser, persistent collection API and native source. Extend their existing interfaces rather than replacing the product with a generic chat mockup.
